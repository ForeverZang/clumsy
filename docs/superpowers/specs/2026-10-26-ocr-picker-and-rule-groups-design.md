# ⑤ 自动测试块交互重构设计：微信式选窗 / 合并开始按钮 / 区域表 + 规则组（AND）

日期：2026-10-26
状态：待用户批准（头脑风暴产出）
分支：feat/ocr-window-auto-loss（基于已发布的 0.3.1 工作区继续开发）

## 1. 背景与动机

0.3.1 真机使用后，⑤ 自动测试块暴露三个体验问题：

1. **选窗割裂**：点「选择窗口…」先弹一个文字列表（0/1/多窗口三种分支），选完还要再点「+ 添加区域」才进入拖框。用户想要微信截图式的一步体验：点一下，自动框定目标程序窗口，直接在亮框上拖区域。
2. **两个开始按钮**：⑤块内白色「开始」与底部绿色「开始影响」接的是同一个入口（`uiToggleActionCb`），用户不理解为什么有两个开始。
3. **单区域规则不够防误判**：一块区域的文字可能被 OCR 误判、或瞬时被弹窗/动画遮挡而误触发切档。需要「区域 A 含某词 **且** 区域 B 含某词，同时满足才触发」的组合规则；同时现有规则行随数量增减改变⑤块高度，对话框忽高忽低。

用户的真实场景（原话确认）：两块文字（如「就绪」与「仓库」）属于同一个游戏状态的两个表现，**一起出现、一起消失**。第二块区域是双保险：单块被认错或被挡住一帧时不应切档。

## 2. 目标 / 非目标 / 反目标

### 目标

- G1：选窗 + 拖区域合并为一次微信式遮罩交互：自动/悬停框定本应用窗口 → 在亮框内连拖多个区域 → 工具条确认。
- G2：⑤块内不再有开始/停止按钮；开始/停止只有底部绿色大按钮一个。
- G3：识别区域与触发规则解耦为两层数据：
  - **区域**：窗口上的一个矩形（编号 R1…，有名称），每 tick 只抓取+识别一次。
  - **规则组**：勾选多个区域并各自配关键词，组内关系为**且（AND）**；组级配置触发时机（出现/消失）、确认帧数、目标丢包率。
  - 关键词挂在「组 × 区域」上：同一个 R1 在组 1 可找「就绪」，在组 2 可找「等待中」。
- G4：区域与组都用**固定行高、表内滚动**的表格展示，⑤块高度不随条目数跳动。
- G5：旧 `ocr_config.txt` 自动升级：每条旧规则迁移为「一个区域 + 一个单成员组」。

### 非目标（本期不做）

- 组间 OR、嵌套组、跨多个窗口的区域。
- 键盘精确输入矩形坐标；区域矩形的二次拖拽编辑（仍靠删除重拖）。
- Windows.Graphics.Capture 抓取方式（v1 仍是 PrintWindow）。
- 内置第三方游戏/应用的预置规则（安全定位不变：只服务用户自己的程序/授权 QA 目标）。

### 反目标（做成了就算失败）

- 选窗遮罩把**别的应用**的窗口框进来（只能框定所选应用 PID 的顶层窗口）。
- ⑤块高度继续随规则数量伸缩；规则组编辑再开一层「弹窗里套弹窗」。
- 任何情况下因 OCR/配置问题影响到无法归属目标应用的数据包（安全铁律不变）。

## 3. 已确认的决策（头脑风暴，用户逐项点选）

| # | 决策点 | 用户选择 |
|---|--------|----------|
| D1 | 同一应用有多个顶层窗口时 | **A：微信式悬停框定**——遮罩内鼠标移到哪个窗口，哪个窗口高亮，点击锁定；唯一窗口时直接进入拖框阶段 |
| D2 | 绿色按钮文案 | **B：永远只叫「开始影响 / 停止影响」**（勾选⑤后行为变化、文案不变；英文 Start/Stop 不变） |
| D3 | 关键词归属 | **B：属于「组 × 区域」成员行**，不在区域上 |
| D4 | 规则组编辑形态 | **B：双击组行弹独立模态对话框**（成员勾选+关键词、触发、帧数、丢包都在对话框里；组表本身只读摘要） |

## 4. 交互设计

### 4.1 微信式选窗遮罩（G1）

入口（沿用现有两个按钮，语义改为同一遮罩的两个入口阶段）。调用方传入 `hadPickedWindow` 布尔，决定完成时是否允许 0 新框：

- **目标窗口行的「选择窗口…」**：无已选窗口时进入 *框定阶段*；已有有效窗口时同样先进 *框定阶段*（便于一步改指别的窗口），再进拖框。
- **「+ 添加区域」**：要求已有有效窗口，跳过框定直接进入 *拖框阶段*；窗口已关闭/最小化则不进遮罩，沿用行内红字提示重选。

前置校验与今天一致：该应用 0 个可见顶层窗口 → 不进遮罩，⑤块内红字提示「该应用当前没有可见的顶层窗口…」。

**阶段一：框定（FRAME）**

- 全屏半透明压暗遮罩（扩展现有 `src/ui_picker.c` 单阶段覆盖窗为两阶段状态机）；枚举所选应用的可见顶层窗口（`captureEnumWindowsForApp`）。
- 只有一个窗口：自动锁定，直接进入阶段二。
- 多个窗口：鼠标悬停的那个本应用窗口**内部保持全亮 + 蓝色描边 + 顶部小标签（exe — 窗口标题）**，其余一切压暗；其他应用的窗口不可点。点击锁定。
- Esc / 右键：放弃并退出遮罩（不改变已选窗口与已有区域）。

**阶段二：拖框（DRAG）**

- 锁定窗口保持亮框，外部压暗；已有的旧区域以橙色虚线框一并显示（编号沿用 R#）。
- 在亮框内按住左键拖出新矩形，边界被限制在窗口客户区内；拖动时显示微信式尺寸提示（宽 × 高）；编号从已有区域数继续（R3、R4…）。
- 可在一次遮罩里**连拖多个**新框。
- 底部工具条：`↩ 撤销上一个框`、`↖ 重选窗口`、`✕ 取消`、`✓ 完成（N 个区域）`；Esc 退出整次遮罩；右键取消当前未完成的拖框。
- **重选窗口（裁决 R1）**：点「重选窗口」从 DRAG 回到 FRAME；本会话已拖出的新框相对旧 HWND 无效，一律丢弃（旧区域是进入遮罩前就存在的，仍保留显示）；重新锁定后编号从头排。HWND 与新框都只在「完成」时提交，故重选 + 取消对既有状态零影响。
- **完成门槛（裁决 R3）**：进入遮罩时*没有*已选窗口（首次选窗）→ 至少 1 个新框，否则完成钮禁用；进入时*已有*有效窗口（「选择窗口…」改指、或「+ 添加区域」）→ 允许 0 新框完成（仅确认/改指窗口，窗口行随之更新）。
- 完成后：窗口行显示该窗口标题（本次锁定的 HWND 作为 session picked window，语义同现状）；新区域进区域表，默认名称「区域 N」（英文 Region N），可在表里改名。
- 遮罩期间目标窗口被关闭/最小化：自动退出遮罩，⑤块红字提示窗口失效需重选，本次拖出的框不落表。

多显示器：v1 覆盖鼠标所在显示器的全屏虚拟屏区域（与现有覆盖窗实现取齐），不跨屏框选。

### 4.2 合并开始按钮（G2）

- 删除⑤块内白色 FlatButton 及其行；`uiOcrCreate` 不再需要 `actionCb` 参数（签名收窄，main.c 与各测试/夹具同步）。
- 底部绿色按钮是唯一开始/停止：
  - ⑤未勾选：行为、文案完全不变（「开始影响 / 停止影响」）。
  - ⑤勾选：点「开始影响」时先走现有 OCR preflight（`uiOcrGlueStart`：配置校验 → 解析 HWND → CSV → 引擎 → seed → worker），任一失败：错误仍显示在⑤块内（折叠态用块外闸门红字、展开态用块内错误行，沿用 0.3.1 修复），驱动不挂载，按钮不变色，**用户能在原地看到原因**。
  - 运行中绿色按钮变红显示「停止影响」（既有逻辑），按下同时停 OCR、CSV 落盘（即现在 `uiStopCb` 的顺序）。
- 运行中⑤块配置区整体禁用（勾选框、表格、参数、窗口按钮），停止后恢复——沿用现有 `uiOcrSetRunning` 的冻结语义，只是不再操作块内按钮。
- i18n：`ocr.start`/`ocr.stop` 两个键删除（随按钮一起没了），新增的遮罩/表格/对话框文案全部中英配对；CSV 与 LOG 保持英文。

### 4.3 区域表 + 规则组表 + 组编辑对话框（G3/G4/D3/D4）

⑤块展开后的布局顺序：

```
目标窗口：  <标题>            [选择窗口…]
┌ 识别区域 ─────────────────────────────┐  固定 4 行高，表内滚动
│ R# │ 名称        │ 位置          │ 删除 │
│ R1 │ 状态图标    │ x y w×h（比例）│ 删除 │
│ R2 │ 仓库名      │ ...           │ 删除 │
└───────────────────────────────────────┘
[+ 拖框添加区域]
┌ 规则组（双击行编辑）──────────────────────────────────┐ 固定 3 行高
│ 组 │ 条件摘要                    │ 触发     │帧│丢包%│删除│
│ 1  │ R1「就绪」 且 R2「仓库」     │ 文字消失时│2 │ 95 │删除│
│ 2  │ R1「等待中, 排队」           │ 文字出现时│2 │ 0  │删除│
└───────────────────────────────────────────────────────┘
[+ 新建规则组]
识别间隔…   ☑画面未变化时跳过识别
（CSV 镜像日志、打开目录，不变）
```

- 行高固定（单行 24px 量级，与现有 IUP 控件齐平），表格自身滚动，⑤块和对话框尺寸不随条目数变化。
- 「位置」列显示归一化比例坐标（诊断用，只读）；名称列可直接就地编辑。
- 删除区域：引用它的组自动移除该成员；组成员变 0 时，组行摘要标红「空组：无区域」，启动校验阻止开始（错误文本定位到组号）。删除区域给一次确认（该区域可能被多个组引用）。
- 双击组行（或选中后回车 / 行内「编辑」 affordance）打开**模态组编辑对话框**：
  - 上半：全部区域的成员列表，每行 `☑ R# 名称 | [关键词输入框]`，表内滚动；未勾选行的关键词框禁用。
  - 下半：触发条件（出现/消失下拉）、确认帧数（≥1 整数）、丢包%（0..100）。
  - 「+ 新建规则组」立即打开该对话框（新组草稿，取消则不入表）。
  - 确定时校验：≥1 个勾选区域；每个勾选区域关键词非空；帧数/丢包数值合法。失败在对话框内红字定位，不允许确定。
  - 取消放弃所有修改（对话框操作自己的草稿副本，确定才提交）。
- 组表「条件摘要」：`R1「就绪」 且 R2「仓库」`（英文 `R1 "ready" and R2 "warehouse"`）；关键词过长时尾部省略，完整内容在编辑对话框里。
- 上限：区域 16、组 16（引擎常量 `OCR_MAX_REGIONS=16` 已在；组上限新定 16），达到上限按钮禁用并提示。

## 5. 数据模型与引擎语义

### 5.1 配置结构（ocr_config.h / ocr_rules.h 演进）

```c
typedef struct {
    char     name[32];
    NormRect norm;                 // 客户区比例矩形
} OcrRegionDef;

typedef struct {
    int  regionIndex;              // 指向 OcrConfig.regions 的下标
    char keywords[256];            // 逗号分隔（, 或 ，），成员内 OR
} OcrGroupMember;                 // 命中 = ocrRuleMatches 同款子串归一化匹配

typedef struct {
    OcrEdge         edge;
    int             confirmFrames;
    int             lossPercent;
    size_t          memberCount;
    OcrGroupMember  members[OCR_MAX_REGIONS]; // 成员按 regionIndex 升序去重
} OcrGroup;

typedef struct {
    char   exeName[128];
    char   windowTitle[256];
    int    intervalMs;
    BOOL   changeDetect;
    BOOL   enabled;
    size_t regionCount;
    OcrRegionDef regions[OCR_MAX_REGIONS];
    size_t groupCount;
    OcrGroup groups[OCR_CONFIG_GROUPS_MAX]; // 16
} OcrConfig;
```

- 纯逻辑层 `ocr_rules.c`：新增组级匹配（成员 AND + 成员内 OR）与组级状态机；现有 `OcrRuleState`/`ocrRuleStep` 直接复用——组在一个 tick 上的合成 `OcrPoll` 喂给它：
  - 任一成员区域本轮抓取/识别 **UNAVAILABLE** → 组本轮 **UNAVAILABLE**（状态机不动；遮挡/抓取失败绝不被解释成「消失」）。
  - 全部可用：所有成员都命中 → **MATCHED**（组 present）；任一成员未命中 → **MISSED**。
  - **出现**：连续 N 帧 MATCHED；**消失**：已 armed 且连续 N 帧 MISSED。单帧认错/遮挡（下一帧恢复）达不到 N，不切档——这是双保险的核心机制。
  - armed 语义不变：组在第一次「所有成员区域都可用」的 tick 才武装，首帧失败不能触发。
- 每 tick 物理抓取仍按**区域去重**：一个矩形只抓一次、只 OCR 一次（变化检测缩略图/lastText 优化挂在区域上）；各组拿同一份区域文本用自己的关键词判定。
- **抓取集合 = 所有组成员引用区域的并集（裁决 R2）**：不属于任何组的区域不抓取、不 OCR（省掉无意义的 PrintWindow+识别）；这类区域在 UI 上仍正常显示，只是不耗资源。
- **启动 seed 门槛维持宽口径（裁决 R2）**：preflight 初始扫描只要求被引用区域并集中 ≥1 个可读成功即放行；没读到的区域在后续第一个全部成员可用的 tick 延迟武装。这样双保险场景里启动瞬间一块区域正好被挡，不会阻止开始。只有被引用区域**全部**读不到时才按现有 `ocr.error.seed` 拒绝启动。
- 同一 tick 多个组触发：按组表顺序取**第一个**触发组的丢包率（与今天规则从上到下、触发档位保持到下一次触发的语义一致）；CSV 每个触发组仍各写一行 `rule_trigger`，但只有第一个带档位切换（与现有多规则事件处理取齐）。
- 触发后档位保持，直到另一组触发或手动停止（现有行为，不变）。

### 5.2 持久化与迁移

- 新文件格式（UTF-8 key=value，容忍解析原则不变）：
  - 区域：`region.<i>.name=...`、`region.<i>.x/y/w/h=...`
  - 组：`group.<j>.edge=appear|disappear`、`...frames=`、`...loss=`、`group.<j>.member.<k>.region=<i>`、`group.<j>.member.<k>.keywords=...`
  - 顶层 exe/window/interval/changeDetect/enabled 沿用现键。
- **迁移**：加载器识别旧格式（`rule.N.*` 行）时，每条旧规则转成 1 个区域（取其 name/norm）+ 1 个单成员组（取 keywords/edge/frames/loss）；加载成功后首次保存写新格式。无法识别的行照旧跳过，不报错。
- CSV：`rule_trigger` 行的身份字段从区域/规则改为**组号 + 摘要名**（如 `group 1`），`text` 放触发文本（多成员时按成员顺序拼接）；列结构不变，既有时间线工具/验收脚本同步小改。

## 7. 安全与既有约束（不变项）

- 安全铁律：无法归属到目标应用的包一律原样放行。OCR 全程只经 `uiSimpleApplyExternalLoss → simpleSetLoss`（双重 clamp），不碰过滤/shouldAffect/包路径。
- 启动失败关闭：preflight 任一步失败，⑤块回到空闲态、不挂驱动、不产生半截 CSV。
- 仅 x64 gcc（OCR）、PrintWindow v1、间隔下限 200ms 默认 500ms、文件 ≤800 行 / 函数 ≤50 行、malloc 全部检查、UI 中文双语、日志英文。
- 物理验收：真机 UAC 提权 smoke 仍挂起（elevate.c + error.elevate* 文案未入库），不在本次范围。

## 8. 留给实现者决定的小事（设计不锁死）

- 两张表的具体像素行高与可见行数（区域 4 行 / 组 3 行为建议值）、列宽分配。
