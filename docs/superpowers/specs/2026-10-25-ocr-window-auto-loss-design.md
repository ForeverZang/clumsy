# 自动测试（OCR 触发丢包）设计

日期：2026-10-25
分支：`feat/ocr-window-auto-loss`（基于过程定向新手 UI 分支）

## 1. 意图与为什么

为**开发者对自己（或获得授权）的应用做弱网测试**提供一个“自动按剧本切档的测试员”：clumsy 已经能按镜像名定向影响某个应用并调节丢包率，本功能在此之上，让程序观察被测应用窗口上指定小区域的文字变化，在预期时机自动切换丢包档位，并把全过程写入时间线，供人工分析断线/重连流程的表现。

**使用范围限定**：工具不内置任何第三方应用/游戏的识别规则；区域、关键词、档位全部由使用者自己配置。工具面向对自有程序的 QA，不提供也不暗示对线上第三方服务的使用方式。

典型剧本（来自需求）：被测程序右下角状态栏常驻文字，进入输入状态时文字消失；中央在断线时出现“重连”。配置两条规则：

1. 右下区域文字「消失」→ 丢包率切到 95%（制造断线）；
2. 中央区域出现「重连」→ 丢包率切到 50%（给重连流程一个可恢复的中度弱网）。

档位触发后保持，不自动回退；是否恢复、何时恢复由测试员手动停止决定。工具不做通过/失败判定，只忠实记录。

## 2. 目标 / 非目标 / 反目标

### 目标

- 在现有「基础功能」页内新增第⑤块「自动测试（OCR）」，默认折叠，勾选启用后展开；不启用时界面与行为和当前版本完全一致。
- 两步目标选择：先选应用（镜像名，复用现有过程定向），再选该应用的一个顶层窗口。
- 在目标窗口上拖拽框选一个或多个矩形区域，坐标按目标窗口客户区保存，窗口移动不影响。
- 每个区域可配一条规则：名称、关键词（多个，逗号分隔）、触发方式（出现/消失）、连续确认帧数、目标丢包率（0–100%）。
- 轮询间隔、连续确认帧数、变化检测开关、初始档位来源均可由使用者配置。
- 运行时规则接管丢包率，滑块程序化跟随并禁用手动拖动。
- 全程输出 CSV 时间线，同时在页面底部只读滚动日志中实时显示，标注 CSV 完整路径并可一键打开所在目录。
- OCR 栈：RapidOCRLite，精确模式，`ch_PP-OCRv6_small`，INT8 量化模型，关闭 cls 方向分类器；业务层全部用 C。

### 非目标

- 不做通过/失败自动判定、成功率统计、录像。
- 不做基于规则的自动回退/自动恢复档位。
- 不做整窗 OCR、全屏 OCR、OCR 结果的自由脚本化。
- 不内置任何具体应用的预置规则。
- 不做多语言 OCR 模型切换（首版只随包中文小模型；英文由同一模型覆盖识别）。

### 反目标（做成了就算失败）

- 默认界面为不用 OCR 的人增加任何视觉或操作负担。
- OCR 误识别导致频繁误切档（必须有帧确认与变化检测兜底）。
- OCR 线程卡顿拖死 UI，或 UI 线程直接跑 OCR。
- 时间线含糊：每次档位变化必须能区分来自规则、滑块初始化还是手动停止。
- 抓不到画面时假装识别成功。

## 3. 现状与复用

- 过程定向：按镜像名归属包（procmap/flowmap/targeting），安全铁律不变——无法归属到目标应用的包一律放行，OCR 功能不改变任何包处理语义，只在运行时改写**目标应用**的丢包百分比。
- 基础页（ui_simple.c）：应用下拉、方向、丢包滑块（0–100，permyriad）、定时恢复、流量图、开始/停止。OCR 块作为第⑤块折叠区挂入。
- 标签页：基础/高级两页永久挂载、VISIBLE+FLOATING 切换（本分支基线已修复切换丢状态问题）。
- 高级模块与本功能互斥关系沿用现有开始/停止管线：OCR 自动化只改新手丢包这一档（dropModule 等效参数），不触碰高级 8 模块；参数化（CLI）模式下 OCR 块不启用。
- i18n：所有界面文案走 i18n key，中/EN 双语；CSV 表头用英文（日志保持英文的既有约定），界面标签随语言。

## 4. 用户流程

1. 选中目标应用（复用应用下拉；“不限制应用”时 OCR 块不可启用，必须选具体应用）。
2. 勾选「启用自动测试（OCR）」，块展开。
3. 「选择窗口」：弹出该镜像名对应的可见顶层窗口列表（标题；无标题则显示 `类名 宽x高`），选一个。
4. 「添加区域」：进入全屏半透明遮罩（只让目标窗口清晰），在窗口上拖一个矩形，松开后回到主界面，区域列表新增一行。
   - 遮罩上可拖多个框（每拖完一个“保留”，右键/Esc 结束）；首版也支持每次按钮只加一个，实现时取简单者。
   - 坐标存为相对客户区的归一化比例（x/w, y/w, w/w, h/h，float），窗口缩放/DPI 变化后按比例还原；归一化由实现者在文档外决定，属于我的默认（见 §11）。
5. 每行区域规则填：名称（默认“区域1”）、关键词（逗号分隔）、出现/消失（下拉）、连续帧数（默认 2）、目标丢包率%（0–100）。
6. 参数区：轮询间隔 ms（默认 500，下限 200）、连续确认帧数默认值（新行继承）、变化检测（默认开，差异阈值内部默认）。
7. 点基础页绿色「开始影响」：WinDivert 按滑块当前档位挂接，OCR 观察器启动；第一条规则触发前丢包率 = 滑块当前值。
8. 运行中：规则命中 → 丢包率切到规则目标值并保持；滑块程序化跟随、禁用；所有事件进入 CSV 与滚动日志。
9. 点「停止」：OCR 观察器停止，WinDivert 拆除，滑块恢复可编辑；CSV 落盘保留，日志内容保留到下次开始。

## 5. 规则引擎（纯逻辑，可单测）

每个区域一台小状态机，轮询周期驱动：

- 输入：本周期该区域 OCR 文本（抓帧失败为“不可用”，变化检测跳过时复用上周期结果）。
- 匹配：关键词列表 OR；先对 OCR 文本做规范化（去空白、大小写不敏感），子串包含即命中。
- 「出现」规则：连续 ≥ N 个周期命中，且上一个稳定状态为“未命中” → 触发一次。
- 「消失」规则：连续 ≥ N 个周期**未命中**，且上一个稳定状态为“命中” → 触发一次。
  - 起始基线：启用/开始时若区域文字存在，「消失」规则的初始稳定状态记为“命中”（即先看见状态栏，之后消失才触发）；「出现」规则初始为“未命中”。
  - 抓帧不可用的周期**不参与**确认计数（既不算命中也不算未命中），连续计数保持不变，并写一条 `capture_unavailable` 事件（限频，每 5 秒最多一条）。
- 触发动作：设置全局目标丢包率（百分比→permyriad），写 `loss_change` 事件，来源标记 `rule:<区域名>`。
- 沿边语义：稳定状态不翻转就不重复触发；多个区域同一周期命中时按区域列表顺序触发，最终档位为最后一条规则的值，并各写一条事件。
- 手动停止：来源 `manual_stop`；开始时初始化档位写 `loss_change` 来源 `initial_slider`。

纯函数输入用结构体描述（周期结果数组 + 当前状态），输出（新状态、是否触发、目标档位），不依赖 IUP/OCR，全部进单元测试。

## 6. 抓帧

- 目标 HWND 来自窗口选择步骤；每周期：
  1. 校验窗口仍存在、可见、非最小化（`IsIconic`）；不满足 → 不可用。
  2. 取客户区矩形（`ClientToScreen`），按区域归一化坐标 + 当前 DPI（GetDpiForWindow / 线程 DPI 感知）还原像素矩形。
  3. **PrintWindow(hwnd, PW_CLIENTONLY | PW_RENDERFULLCONTENT)** 抓客户区到 BGRA 位图，裁剪区域。
  4. 变化检测：与上一帧该区域缩小小图（如 32px 宽）做平均绝对差，低于阈值视为无变化，复用上轮 OCR 文本，不跑 OCR。
  5. 无 PrintWindow 结果（全黑检测：位图方差为 0 且上一帧非黑）连续 M 次 → 该窗口标记 PrintWindow 失败，运行期内改走 **Windows.Graphics.Capture**（WGC）抓该窗口，按客户区裁剪；WGC 用一小段 C++/WinRT 或裸 COM 实现，对业务层暴露 C 接口。
- 独占全屏 / 最小化：两种路径都失败时记不可用（§5）。
- 抓取与 OCR 在**专用后台线程**执行；线程与 UI 之间只传不可变快照与事件。
- 这是实现风险最高的一块，先 spike（§10）。

## 7. OCR 接入

- 产物：RapidOCR 静态库（ncnn 内核）+ `c_api.h`；模型 `ch_PP-OCRv6_small` 的 det/rec INT8 文件随包分发（`models/` 目录，与 exe 同目录），关闭 cls。
- 调用链（后台线程，每区域每周期一次）：BGRA→RGB/RGBA 输入 → det 得到文本框 → 裁剪 → rec（LightSVTR+CTC）→ 拼接文本；检测/识别参数走“精确模式”的默认档（spike 后把实际参数固化）。
- 只识别小区域：det 输入像素面积小，耗时可控；spike 实测 300/500ms 间隔下的 CPU 占用与漏检率。
- 业务层（ui_simple/规则引擎/时间线）全部 C；允许 `capture_wgc.cpp`、`ocr_bridge.c` 这样的薄层，异常/错误全部翻译成 C 返回码与英文 LOG。
- 模型加载失败、OCR 初始化失败：开始时弹内联错误（不弹原生框），OCR 块给出红字，WinDivert 不挂接。

## 8. 界面（基础页第⑤块）

折叠条：`☑ 启用自动测试（OCR）`。展开后自上而下：

1. 目标窗口：应用名只读展示 + 「选择窗口…」按钮 + 已选窗口标题只读行；
2. 区域规则表：每行 = 名称输入 | 关键词输入 | 出现/消失下拉 | 确认帧数 | 目标档位% | 「删除」；上方「添加区域（拖框）」按钮；
3. 参数：轮询间隔（IupText 数字）、变化检测（勾选）；
4. 开始/停止按钮（本块内一份，与基础页主按钮同一回调、同一状态）；
5. 只读滚动日志（IupMultiLine，固定高度约 6–8 行，追加后自动滚到底）；
6. 日志下方：`CSV: <完整路径>`（FlatLabel 预留宽度）+ 「打开目录」按钮（`explorer.exe /select,<csv>`）。

运行中：窗口选择、区域表、参数、启用勾选全部禁用；日志与停止可用。i18n 新增 key 前缀 `ocr.*`。窗口宽度沿用基础页现有宽度，区域表超宽时内部滚动，不把主窗口撑宽（实现时以私有桌面截图验收中/英两种语言不裁切）。

## 9. 时间线 CSV

- 目录：`%LOCALAPPDATA%\clumsy\ocr-runs\`（目录不存在则创建，创建失败回退 exe 同目录并 LOG）；文件名 `YYYYmmdd-HHMMSS.csv`，开始时创建，停止时关闭。
- 表头（英文）：
  `time_ms,time_local,event,region,ocr_text,keyword,edge,loss_percent,source,note`
- 事件类型：`session_start`、`loss_change`、`region_match`、`region_miss`（仅稳定态翻转/触发相关，逐帧不写）、`rule_trigger`、`capture_unavailable`、`ocr_init_failed`、`session_stop`。
- CSV 转义：字段含逗号/引号/换行时标准双引号包裹；UTF-8 BOM，Excel 直接打开中文不乱码（我的默认，见 §11）。
- 滚动日志显示人类可读行（中文界面中文行、英文界面英文行），与 CSV 行同一事件、同一 time_ms；它不是 CSV 原文镜像，是事件的双语表达，CSV 始终是规范记录。
- 可选：事件截图（每条 `rule_trigger` 存区域 PNG 到 `ocr-runs\<session>\`），首版做开关、默认关。

## 10. Spike（写产品代码之前，一次性抛弃型验证）

1. **OCR 链接/模型**：msys2 mingw64 gcc 编译一个最小 C 程序链 RapidOCRLite 静态库 + `c_api.h`，加载 INT8 det/rec，对三张样例图（状态栏“仓库”、中央“重连”、无文字）识别，记录：模型文件清单与总体积、初始化耗时、单区域单帧耗时（det+rec，毫秒）、连续 20 次识别的文本稳定性、许可证。失败/无 C binding → 带回重新选栈。
2. **抓帧**：对一个 Unity/D3D11 示例窗口（被测程序或开源 demo）分别试 PrintWindow 与 WGC，遮挡窗口、移动窗口、最小化三种状态，记录成功率与耗时。
3. 用 spike 数据确定默认轮询间隔、变化检测阈值、300ms 档可行性。

spike 代码不进产品树（放 build/ 或独立 scratch 目录），通过后再写计划。

## 11. 实现者可自行决定的默认（我的取舍）

- 区域坐标用客户区归一化比例而非像素。
- CSV 放 LocalAppData，UTF-8 BOM，表头英文。
- 事件截图默认关。
- 滚动日志是事件的双语可读表达，不是 CSV 镜像。
- 区域拖框首版可以“一个按钮加一个框”，多区域靠多次添加。
- 轮询下限 200ms；变化检测阈值 32px 缩略图 MAD，spike 后可改。
- WGC 允许 C++ 薄层；其余新代码全 C。
- 文件 ≤800 行、函数 ≤50 行、每个 malloc 检查、错误显式处理，遵循仓库既有规则。

## 12. 验收

- 规则引擎纯逻辑单测：出现/消失沿边、确认帧数、起始基线、不可用周期不计入、多规则同周期顺序、丢包率换算。
- 抓帧/OCR 以手动程序验收：对一个**测试夹具窗口**（自有程序，可放一个 TextBlock 显示“仓库”，按钮切换隐藏，并能在中央显示“重连”）跑完整剧本，时间线出现且仅出现预期事件与 0→95→50 两次档位变化。
- 不启用 OCR 时，现有全部 §7 验收与 11 个单测不受影响（全量绿）。
- 中/EN 界面截图：折叠态与展开态无裁切，日志滚动与路径显示完整。
- 连续运行 10 分钟（500ms 周期）无句柄增长（manual_leak 模式扩展），UI 不卡。
